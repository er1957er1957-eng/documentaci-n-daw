# Autenticación y autorización

## Objetivo
Cada usuario del sistema debe acceder mediante credenciales verificadas y recibir únicamente los permisos necesarios para su rol.

## Roles disponibles
- Administrador
- Técnico
- Operador
- Cliente interno

## Flujo de autenticación
1. El usuario introduce email y contraseña.
2. El backend valida la credencial con el servicio de autenticación.
3. Se genera un token JWT con expiración.
4. El frontend guarda el token y reutiliza la sesión.

## Control de permisos
Los permisos se gestionan por rol y se validan en cada acción sensible:

```ts
if (!user.hasPermission('incidencias:resolver')) {
  throw new Error('No autorizado');
}
```

## Seguridad recomendada
- Usar HTTPS en producción.
- Rotar tokens periódicamente.
- Guardar secretos en variables de entorno.
- Evitar el almacenamiento de sesión en localStorage cuando no sea necesario.

## Casos de uso
- Un técnico puede cambiar el estado de una incidencia asignada.
- Un cliente solo puede consultar el estado de sus propios reportes.
- Un administrador puede gestionar permisos y métricas del sistema.
